
## 6. File-by-File Explanation

### 6.1 Entry Points

#### `web_app.py` (~2,930 lines) — the Flask REST API
The single production surface. Responsibilities:

1. **Static + health** — `/` status page, `/api/health`, `/api/azure/health` (reports Cosmos
   and Storage reachability), and `/images/<session_id>/<filename>` serving the rendered
   inspection page images written by the report builder.
2. **Authentication & sessions** — `/api/auth/login`, `/api/auth/logout`, `/api/sessions`
   (list active sessions), `/api/sessions/<id>` (terminate). Sessions are held in an
   in-process store; see [§13 Known Limitations](#13-known-limitations).
3. **Users, profile & verification** — `/api/users/me` plus password change, notification
   preferences, verification status, admin-triggered verification email, and the public
   `/verify-email/<token>` landing route.
4. **Generic resource CRUD** — `/api/<resource>` and `/api/<resource>/<id>` handle
   `users`, `projects`, `documents`, `inspections`, `results`, `violations`, `coordinates`
   through `src/resource_schema.py` validation and `src/database/repositories.py`.
5. **Inspections** — `/api/upload` (store the session's Master/Sample PDFs),
   `/api/inspect` (run the pipeline), `/api/inspections` (list/create),
   `/api/inspections/<id>` (fetch/delete), `/api/inspections/<id>/file` (download the
   stored PDF), `/api/crop_inspect` + `/api/crop_logs/<session_id>` (Crop Compare).
6. **Setup & configuration** — `/api/setup/levels-comments` (GET/PUT),
   `/api/inspections/<id>/comments` and the per-difference comment PUT.
7. **Reports by email** — `/api/inspection/share` accepts a base64 PDF, checks size and
   allowed extensions, and hands it to `send_inspection_report_email()`.
8. **Audit trail** — `/api/audit-logs`, `/api/audit-logs/<log_id>`, `/api/audit/events`.
9. **Storage helpers** — `/api/storage/upload`, `/api/storage/download`.

Every route is wrapped in explicit try/except blocks that log the real exception
server-side (via `src/logger.py`) while returning a short, safe JSON message to the
client — that is why a browser-visible "please try again" message always has a matching
`[EMAIL-VERIFY] …`-style line in `artifacts/logs/`.

#### `application.py` (~51 lines) — offline CLI
Argument-driven, dependency-light entry point:

```
python application.py --master "Data/Master/file.pdf" --sample "Data/Sample/file.pdf"
```

It imports `run_text_inspection` and `save_report` from
`src/pipelines/comparison_pipeline.py` and writes the CSV reports to disk. No Flask, no
Cosmos, no Blob. This is the tool to use when you want to reproduce a detection result
without involving the web stack.

#### `seed_users.py` (~113 lines) — default user provisioning
Inserts the two baseline accounts into the Cosmos `users` container using
`src/password_utils.hash_password()` so nothing plaintext is ever stored. Run it once on
a fresh environment. It is idempotent in practice: re-running updates the seeded documents
rather than creating duplicates.

#### `setup.py` (~16 lines) — packaging metadata
`setuptools` metadata (`name="globalvision-replace"`, version, `find_packages()`) and the
`install_requires` list, enabling `pip install -e .` from the backend directory.

#### `requirements.txt` (~14 lines)
Runtime dependency pins/lists: `opencv-python`, `numpy`, `scikit-image`, `PyMuPDF`,
`matplotlib`, `pandas`, `openpyxl`, `rapidfuzz`, `Pillow`, `scipy`, `pytesseract`,
`azure-cosmos`, `azure-storage-blob`, `azure-identity`.
